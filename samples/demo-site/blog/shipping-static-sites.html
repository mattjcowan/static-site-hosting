Shipping static sites from a zip

22 July 2026

The naive way to update a static site is to copy the new files over the old ones. It works right up until someone loads the page halfway through the copy and gets a new index.html pointing at a stylesheet that has not landed yet.

Releases instead

Each upload is extracted into its own directory, named for the moment it arrived: 

/data/sites/demo.site/
  site.json                    ← which release is live
  releases/
    20260722-101503-4a1c/      ← previous
    20260801-093311-9be2/      ← current

Only once every file is written does the pointer in site.json move. A request either sees the whole old release or the whole new one, never a mixture. A failed upload leaves nothing behind but a deleted staging directory.

Rollback is just a pointer

Because the previous release is still sitting there untouched, going back is not a redeploy — it is a one-field edit. The last few releases are kept and the older ones are pruned as new ones arrive.

Deploying from CI

curl -H "X-Api-Key: $SSH_KEY" \
     -F "file=@site.zip" \
     https://deploy.example.com/api/v1/sites/demo.site/deploy

Same code path as the drag-and-drop box in the browser, same atomic swap at the end.
