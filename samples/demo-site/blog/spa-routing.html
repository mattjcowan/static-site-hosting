Routing without a router

1 August 2026

A single-page app owns its own URLs. The server's only job is to hand back the right index.html no matter how deep the path goes, and let the client take it from there.

The walk up

For a request to /blog/deeper/still/missing, the host looks for, in order: 

/blog/deeper/still/missing
/blog/deeper/still/missing.html
/blog/deeper/still/index.html
/blog/deeper/index.html
/blog/index.html          ← found
/index.html

The first one that exists wins. Nest an app under /blog/ with its own index.html and it keeps its own routes; leave the folder empty and requests fall through to the site root instead.

Assets are not routes

One deliberate exception: a request for something like /assets/chunk-4f2a.js that does not exist returns a real 404 rather than HTML. Serving an HTML document with a JavaScript content type produces errors that look nothing like the actual problem, so a missing asset is allowed to fail honestly.

Browsers ask for text/html when you navigate and something else when they fetch an asset, which is exactly the signal needed to tell the two apart.

Try it

  • /blog/deeper/still/missing → the blog index
  • /nowhere/at/all → the site index
  • /assets/chunk-4f2a.js → an honest 404
